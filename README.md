## Как подключить свой

Форкните этот репозиторий, добавьте свои сервисы и укажите панели:

```bash
DOCK_REGISTRY_URL=https://raw.githubusercontent.com/<вы>/<ваш-реестр>/master
```

Панель перечитывает каталог при старте, раз в час и по кнопке. Скачанное
кэшируется на хосте — недоступный гитхаб не ломает уже поставленные сервисы.

`raw.githubusercontent.com` отдаёт файлы через CDN с кэшем в несколько минут,
так что свежий коммит доезжает до панелей не мгновенно.

## Раскладка

Файлы обязаны лежать в корне репозитория:

```
registry.yaml              индекс: что вообще есть в каталоге
stacks/<id>/stack.yaml     описание сервиса
stacks/<id>/compose.yaml   compose-документ, если он не встроен в описание
stacks/<id>/files/*.tmpl   шаблоны конфигов, которые сервис кладёт себе в каталог
```

Чтобы добавить сервис, нужно завести `stacks/<id>/stack.yaml` и дописать запись
в `registry.yaml`. Обязательны у записи только `id` и `path`; `id` обязан
совпадать с `id` внутри описания и с именем каталога.

## Как описывается сервис

`stack.yaml` (apiVersion `dock/v1`) описывает сервис так, чтобы он приезжал уже
настроенным — с конфигами соседей, а не «вот образ, дальше сам».

```yaml
apiVersion: dock/v1
kind: Stack
id: observability
name: grafana + prometheus + loki
version: 1.0.0
category: мониторинг
summary: 'Наблюдаемость из коробки.'
primary: grafana                 # чей порт и журнал показывать на карточке

inputs:                          # из них панель строит форму установки
  - key: PORT                    # ключ = имя переменной окружения
    label: Порт grafana
    type: port
    default: 3000
    hostPort: true               # панель проверит, что порт свободен
  - key: ADMIN_PASSWORD
    type: secret
    generate: password           # пустое поле → сгенерируется
  - key: ENABLE_LOKI
    type: bool
    default: true

profiles:                        # родные compose-профили, включаемые булевым инпутом
  - name: loki
    when: ENABLE_LOKI

volumes:                         # создаются заранее и с нужным владельцем
  - path: data/grafana
    owner: '472:0'
  - path: media/films            # shared — путь от /home/dock, а не от стека
    shared: true
    owner: '1000:1000'

files:                           # рендерятся в каталог стека
  - path: prometheus/prometheus.yml
    template: files/prometheus.yml.tmpl
  - path: grafana/provisioning/datasources/loki.yaml
    template: files/ds-loki.yaml.tmpl
    when: ENABLE_LOKI

compose: compose.yaml            # либо compose-документ прямо здесь

post:
  url: 'http://${DOCK_HOSTNAME}:${PORT}'
  notes: 'Пароль: ${ADMIN_PASSWORD}'
```

### Три решения, на которых стоит формат

**Compose не переизобретается.** Значения инпутов панель кладёт в `.env` рядом с
compose-файлом, подстановку `${PORT}` делает сам docker compose. Зависимости,
профили, healthcheck'и и пересоздание изменившегося — тоже его работа.

**Свой шаблонизатор умеет ровно одно — `${VAR}`.** Он нужен только для конфигов
сервисов (`prometheus.yml` и подобных), которые compose не трогает. Условий и
выражений в шаблонах нет намеренно: файл должен читаться как файл, а не как
программа. Необязательные части включаются через `when` у файла и профили у
сервисов. Экранирование как в compose: `$$` даёт литеральный `$` — это нужно
там, где `${1}` значит своё, например в relabel-правилах prometheus.

**Ключ инпута — это имя переменной окружения.** `ADMIN_PASSWORD` попадает в
`.env`, в шаблоны и в compose под одним именем, без отдельного пространства имён.

### Типы инпутов

`string`, `text`, `port`, `number`, `bool`, `enum`, `secret`, `path`.
У `secret` есть `generate`: `password`, `hex32`, `hex64`, `uuid`, `base64` —
пустое поле в форме заполнится сгенерированным значением.

### Что подставляет сама панель

`DOCK_STACK_ID`, `DOCK_STACK_DIR`, `DOCK_DATA_DIR`, `DOCK_MEDIA_DIR`,
`DOCK_NETWORK`, `DOCK_TZ`, `DOCK_DOMAIN`, `DOCK_HOSTNAME`, `DOCK_PUID`,
`DOCK_PGID`. Перекрыть их инпутом нельзя.

### Общая медиатека

`/home/dock/media` — библиотека, общая для всех медийных стеков: качалка её
наполняет, плееры читают. Внутри `music`, `films`, `shows` и `downloads`.

Каталог оттуда объявляется томом с `shared: true` — тогда панель создаст его
с нужным владельцем до первого запуска и **не удалит** вместе со стеком.
Ссылаться на него в compose нужно через `${DOCK_MEDIA_DIR}`: `DOCK_STACK_DIR`
ведёт внутрь стека, а библиотека живёт снаружи.

Не заводите свой каталог под медиа: смысл соглашения в том, что скачанное
qbittorrent'ом в `music` сразу видит navidrome, без переносов и симлинков.

### Порядок установки

Описание → файлы и каталоги данных с владельцем → и только потом `compose up`.
Обратный порядок — самая частая причина «поставилось, но упало»: докер создаёт
недостающий каталог от root, а grafana (uid 472) писать в него не может.

## Проверить перед коммитом

Поднимите панель, направив её на свою ветку, и поставьте сервис:

```bash
DOCK_REGISTRY_URL=https://raw.githubusercontent.com/<вы>/<ваш-реестр>/<ветка>
```

Описание разбирается строго — панель ругается на конкретное поле и объясняет,
что с ним не так, а не отсылает читать исходники.

## Ветки

`master` — то, что видят все установки. Ломать его больно всем сразу, поэтому
новые сервисы удобнее обкатывать в отдельной ветке.
