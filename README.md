# SHFF Registry — реестр готовых стеков для SHFF Dock

Панель [SHFF Dock](https://github.com/Heisenberg4441/shff-dock) тянет этот
репозиторий по HTTP и показывает его содержимое в каталоге. В комплекте с образом
стеки не поставляются — обновить каталог у всех установок значит запушить сюда
коммит.

## Как панель это читает

Панель ходит на `raw.githubusercontent.com`, поэтому файлы обязаны лежать в корне:

```
registry.yaml              индекс: что вообще есть в реестре
stacks/<id>/stack.yaml     манифест стека
stacks/<id>/compose.yaml   compose-документ, если он не встроен в манифест
stacks/<id>/files/*.tmpl   шаблоны конфигов, которые стек кладёт себе в каталог
```

Адрес прописан в панели по умолчанию и переопределяется переменной
`DOCK_REGISTRY_URL`:

```
https://raw.githubusercontent.com/Heisenberg4441/shff-registry/master
```

Индекс перечитывается раз в час (`DOCK_REGISTRY_TTL`) и по кнопке «обновить»
в каталоге. Скачанное складывается в `/home/dock/registry` на хосте — недоступный
гитхаб не ломает уже установленные стеки и не мешает ставить новые из кэша.

`raw.githubusercontent.com` отдаёт файлы через CDN с кэшем в несколько минут,
так что свежий коммит доезжает до панелей не мгновенно.

## Как добавить стек

1. Завести `stacks/<id>/stack.yaml` — `id` в манифесте обязан совпадать с именем
   каталога и с `id` в индексе, иначе панель откажется ставить стек.
2. Дописать запись в `stacks:` в `registry.yaml`. Обязательны `id` и `path`,
   остальное — то, что видно на карточке каталога.
3. Проверить локально: поднять панель с `DOCK_REGISTRY_URL`, указывающим на свою
   ветку, и поставить стек.

Манифест разбирается строго — панель ругается на конкретное поле и объясняет,
что с ним не так. Полное описание формата `stack.yaml` —
[в README панели](https://github.com/Heisenberg4441/shff-dock#формат-стека).

## Ветки

`master` — то, что видят все установки. Ломать его больно всем сразу, поэтому
новые стеки удобнее обкатывать в отдельной ветке, направив на неё свою панель.
